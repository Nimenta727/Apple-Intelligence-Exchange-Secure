# 真机实验矩阵与验收流程（仅限安全实验）

> 测试环境目标：之前记录的 iOS/iPadOS 27.3 beta 2、Shadowrocket 2.2.93 (3488)。如果设备更新，先记录新版本。**以下步骤不是通过记录，所有未做的项目一律标为未运行。**

## 测试原则

- 使用完全虚构的文本和 aies-probe.invalid；没有真实 DeepSeek Key 的情况下先排除网络接管问题。
- 00 是阻断基线；10 是真实目标域名实验，暂不得当作生产启用；20 和 21 是互斥的虚构域名 A/B 方案。
- 原始千问 REJECT 保留。只有观察到浏览器字符串，不能推断没有网络出站；必须有独立可靠的网络观察。停止 VPN / 不受 VPN 管理的流量不受该规则保障。

| ID | 实验 | 模块与动作 | 通过证据 | 失败/停止条件 |
|---|---|---|---|---|
| E0 | 安全基线 | 只启用 00；触发已知目标域名连接，不安装 Key/CA | 规则命中 REJECT；记录命中时间和网络状态 | 域名出站仍成功、未命中规则：立即停下 |
| E1 | Loopback 请求接管 | 关闭 21；仅启用 20，脚本 Script/aies_boundary_probe.js；Safari 打开 HTTPS 固定路径 | 获得 AIES_BOUNDARY_PROBE_OK，观察脚本调用及 127.0.0.1 映射 | HTTPS 失败/证书错误/不返回标记：记失败或证据不足，不改真实域名 |
| E2 | Fake-IP HTTP Engine | 停用 20；只启用 21，同一虚构测试路径 | 获得固定标记，并记录 198.18.41.221 映射和引擎是否运行 | 不工作则记失败；不要在真实域名试 DIRECT |
| E2-N | 出站独立核验 | 对 E1/E2 分别检查连接层是否出现非预期公网出站 | 独立观测确认无非 loopback 出站，区分 DNS / TCP / TLS / QUIC | 仅看到页面成功或 Shadowrocket 日志不足以证明零出站 |
| E3 | 真实 Siri 网络策略评估 | 保持 00 REJECT；验证相关请求是否被阻止，并评估是否有其他域名 | 可重复观察目标规则是否覆盖预期流量 | 不通过或发现绕行：不得继续 Siri 联调 |
| E4 | SSE 客户端兼容性 | 仅在完成 B1 网络接管安全论证后，以完全虚构文本尝试候选 SSE | Siri/写作工具按预期接收并显示结构化回答，无千问原始请求出站 | 连接不安全或回答被拒：停止并修协议 |
| E5 | DeepSeek 正式联调 | 仅在 E3/E4 安全验证通过后，设置小额专用 Key 并审查开启条件 | 真实 Siri 输入经授权发往固定 DeepSeek，Siri 接收、无千问原始透传 | 任一泄露、Key/CA 日志、超时回退：立即关闭 |
| E6 | 故障及恢复 | 测脚本加载失败、断网、超时、重复回调、VPN 切换、蜂窝/Wi‑Fi | 失败时不透传；恢复后仍遵循隔离规则 | 任何无法保证隔离的环境不发布 |

## 当前执行顺序

优先 E0 → E1 → E1 结果归档 → E2 → E2-N。**没有证据不要跳到 E4/E5。** E1/E2 两个模块不能同时启用。如果 A/B 都未能实现本地响应且零出站，结论是当前 Shadowrocket 配置路径不可行或证据不足，而不是删除 REJECT。

## 机器辅助判定

只对 E1（loopback）提供的 JSON 证据使用 node tools/evaluate-boundary.js evidence.json；PROBE_PASS 表示**虚构域名**满足脚本内的测试条件，不表示已具备真实 Siri 安全代理能力。Fake-IP 方案需要独立记录，其映射与判定条件不同，不能不加修改复用 E1 判定。

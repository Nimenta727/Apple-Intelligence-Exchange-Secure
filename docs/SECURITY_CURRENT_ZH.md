# AIES v0.6 安全与隐私边界

> 此文档描述**已实现的脚本层控制和未验证的设备级安全性**，不是安全认证。新产品路线允许问题送千问；旧“零透传”要求已经取消。

## 数据流和信任边界

1. 用户通过 Siri 产生文本问题；Shadowrocket 在目标域名请求阶段尝试读取它。
2. 原始请求**允许继续到千问**；千问可能记录、处理、生成答案。不能宣称隐私隔离。
3. Shadowrocket 响应阶段尝试通过本地保存的 DeepSeek Key 调用官方 DeepSeek API；DeepSeek 同样接收该文本。
4. 脚本只接受已识别的 SSE 结构，以 DeepSeek 内容重建回答字段。模型失败、SSE 未识别等*脚本能介入的故障*尝试改写为 502。
5. 若 VPN、MITM、脚本、请求/响应关联或 Siri 客户端绕过钩子，**无法阻止千问原生答案被展示**。这是目前“最终答案一定来自 DeepSeek”的最大剩余风险。

## 目前代码具有的安全措施

- 目标 Host/Path 与 Siri 文本 POST 白名单；不支持视觉、写作或任意站点。
- DeepSeek HTTPS Endpoint 固定，无 URL 传入密钥、模型路由器、第三方 Dashboard。
- 禁止脚本级自动回退千问，遇未知事件不照搬千问原文；只接受完整的 DeepSeek 文本回答。
- 短期请求关联 token、长度和事件数限制、超时/重复回调保护、固定阶段日志。
- 两个运行钩子固定到同一个 Git commit，避免运行脚本被开发分支意外更新。
- 默认使用用户自备 API Key，本地提供一次性配置/清除脚本；**切勿提交或发送真实 Key**。

## 尚未解决或不作保证

- `$persistentStore` 会暂存请求文本；逻辑 TTL **不等于存储自动物理擦除**。崩溃、Siri 中断、系统重启可能遗留记录。不能保证设备本地加密等级。
- 会话 token 通过自定义请求头发送给原上游；虽不直接包含问题文本，仍增加上游可见元数据。
- MITM 所用本机根证书扩大信任边界；仅为必要主机启用解密，测试后及时停用并按需撤销信任。不可共享 CA 私钥。
- 真实 SSE 的分块、压缩、事件变更与 Shadowrocket 对 Response Body 的可见性还未得到真机证据。
- 无法保证脚本不运行、VPN 断开、蜂窝/ Wi-Fi 切换、系统缓存时不会出现千问回复；不能描述为系统级 fail-closed。
- 版本脚本目前以固定 commit 引用，但模块文件从开发分支引用。正式发布应以固定 tag / release artifact 管理。
- DeepSeek `deepseek-flash` 模型 ID、计费和接口可用性应以安装时的官方文档及实际 API 响应核查；当前没有真实 Key 联调的独立证据。

## 停止、回滚和发布禁止事项

- 未真机验证之前，不得标记“已实现绝对 DeepSeek-only”或“生产稳定”。
- 检测到千问答复、无法修改 SSE、请求/响应串话、密钥泄露或响应绕过时：关闭 60，按安装指南恢复旧 00（如用户仍需要阻断模式）。
- 不通过关闭测试、修改验收描述或上传真实请求来获得 CI 绿色。
- 只有 P4 故障矩阵及真实 Siri UI 验收通过，才评估发布 Beta/Stable；若宿主级回退不可控，明确声明支持范围而非作出保证。

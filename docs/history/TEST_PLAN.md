# Shadowrocket 真实设备验证计划（实验版本）

历史 T01–T14 发布验收清单；当前优先采用 [E0–E6 实验矩阵](../EXPERIMENT_MATRIX_ZH.md)，其中 10 模块及真实 Key 相关项目**尚不可执行**。现有项目仅通过离线 JavaScript 测试。**本计划全部属于“待人工执行”，不是通过记录。**

| 编号 | 测试 | 通过条件 |
|---|---|---|
| T01 | 仅启用 00 Lockdown，无 CA、无 API Key | 目标千问域名连接被 REJECT |
| T02 | VPN 停止 | 明确记录规则不再有保障，不宣称设备级隔离 |
| T03 | 安装本人新生成的 CA | iOS 根证书信任成功，MITM 主机列表仅包含指定域名 |
| T04 | 仅启用 10 Lab，保持 REJECT | 明确观测 request mock 是否在 REJECT 规则前/后执行 |
| T05 | 未配置 DeepSeek Key | 不向 DeepSeek 发请求，不允许千问请求透传 |
| T06 | 本地脚本路径错误 | 请求失败且无千问流量；若透传立即停止实验 |
| T07 | 使用小额专用 Key 发问 | 发往 DeepSeek 的请求为固定 HTTPS Endpoint，回答可在 Siri 正常显示 |
| T08 | DeepSeek API 401/5xx/超时/断网 | 不回退千问、不泄露 Key 或 Prompt 到日志 |
| T09 | 视觉智能包含图片 | 当前拒绝请求，**不发送图片至 DeepSeek** |
| T10 | 并发两次不同文本 | 两次请求无串话；不使用跨请求全局 Prompt 缓存 |
| T11 | 匹配域名的未知路径 | 拒绝，不转发 |
| T12 | 手机切换 Wi-Fi/蜂窝网络 | 逐一复测代理、证书和 REJECT 状态 |
| T13 | 使用 HTTP/3 和其他相关域名 | 确认未出现流量漏网；无法观测的项目不得标记为通过 |
| T14 | 临时 Key/证书清理 | 删除临时脚本、吊销测试 Key 后无法再次调用 |

## 记录建议

只记录：日期、iOS 版本、Shadowrocket 版本、脚本提交 SHA、测试编号、是否见到已授权 DeepSeek HTTPS 请求、是否看到任何千问流量、Siri 是否成功、失败码。**绝对不要把真实用户提问、Authorization Header、API Key、CA 私钥、完整网络抓包上传到 Issue 或 PR。**

## 发布验收门槛

所有 T01–T14 在目标 iPhone 上实测通过，且能通过独立抓包证实“原始请求未送千问”，才有条件把项目从 **lab** 标记为可用。仅仅看到 Siri 回答成功，不等于隐私隔离成功。

可先在电脑离线执行：

```bash
npm run build
npm run check
```


## 0.2.0-lab 额外回归与设备门槛

Node 测试包括域名伪造、方法/场景白名单、无效内容类型、图片及未知结构、密钥缺失、上游异常、超时、迟到响应、重复回调以及 REJECT 配置校验。请额外在真机确认源脚本路径可解析、请求脚本与 REJECT 顺序、VPN 中断时的实际出站、生成 SSE 兼容性及 Wi-Fi/蜂窝切换行为。任何未通过项均须维持 LAB 未验收状态。
